# 用用户提供的素材剪辑

支持照片、自拍视频/航拍/现场视频、屏幕录制、独立录音、音乐、logo与已有工程。不要求先转为图片，也不强制生图、上网找替代素材或合成配音。目标是从实际内容中取舍、排序和包装，代码引擎承担可编辑时间轴与画面运动。

## 先盘点再编排

1. 读取文件清单并检查可访问性，用ffprobe检查时长、尺寸、帧率、旋转、音轨；图片检查方向、分辨率与比例。不能读取的文件单独列出，不假装已看过。
2. 实际查看关键画面，按需做低清预览/联系图；需要保留讲话时审听或转录并核对关键句。只看缩略图不能推断整段内容，没有试听条件就标明原声尚未审核。
3. 给素材稳定assetId，按内容标注可用段、主体、地点、清晰度、构图、声音质量与重复情况；按宣传主线筛选，不因文件编号直接顺排。
4. 用户文件优先。只有存在具体缺口时，才提出补拍、补充材料或另找授权素材；由用户确认素材方案。人物、地点、产品、数据不能按文件名擅自认定。

需求关允许只做初步盘点；文案关使用实际可支持的表述；详细取段、时间线和原声方案在分镜关交用户确认。若只是已有短片局部修改，直接检查相关段并执行已授权修改。

## 非破坏性取段

原件保留在用户指定位置或项目sources/，不覆盖、不重命名、不删除。工程引用原件或复制到项目自己的素材目录；外部原件路径要在交付时说明。代理文件、降噪、转码和变速音轨作为派生文件保存在项目.tmp/或工作素材目录，并记录其源文件。

共享镜头表中，视频片段至少记录如下信息，时间用秒或明确源fps的帧数，统一采用入点包含、出点不包含：

| 字段 | 含义 |
| --- | --- |
| assetId / sourcePath | 对应原件与实际路径 |
| sourceIn / sourceOut / sourceFps | 源入出点与帧率；不把成片fps当作源fps |
| from / durationFrames | 成片所在帧与时长，按成片fps |
| playbackRate | 变速倍率；正向恒速片段成片秒数=(sourceOut-sourceIn)/playbackRate |
| fit / focalPoint | 适配、裁切和需保留的主体位置 |
| audioPolicy | keep / mute / duck / separate；记录原声用途、音量与淡化 |
| purpose | 此段支持的文案/信息，以及必要的弃用或待定原因 |

校验0≤sourceIn<sourceOut≤源时长，倍率为正，片段持续时间一致；转场重叠、冻结帧、变速曲线另行标注，不能套用恒速公式。取段过短、分辨率不足、竖转横裁掉主体时给可观察的问题和替代建议。

可以在引擎内引用源片段并设入点，也可用FFmpeg输出派生片段。具体视频/音频组件、属性和截取命令按项目锁定版本文档核实，不编造API。需要精确切点时验证解码结果；单纯流复制可能落在关键帧边界，不能保证逐帧准确。每次导出确认未把整个源音轨叠进成片。

## 原声、录音与音乐

用户提供录音不自动代表“最终旁白”；先识别用途。提出适合当前片子的具体方案：关键现场原声保留、嘈杂段静音，或独立旁白配BGM。分镜表标出原声保留时间段和配乐避让。已明确的用户选择沿用，不重复询问。

保留有用环境声可以增强真实感；人声与旁白重叠会影响理解时，拆开时间或避让音量。用户要求保留原声时不擅自静音或更换合成声音。加速有人声片段需保持可懂度，处理音高并重新对齐字幕。口播提到旧名字/旧数据时，把冲突句和时间点交用户取舍，在解决前不宣称声画一致。

文件提供不等于同意把素材公开发布到GitHub。视频项目保存许可/来源说明，不能把用户原片、录音、商业音乐或个人数据放进Skill仓库和发布包。

## 边界与异常

从较长素材中抽选已定位或可核实的短片段制作30—90秒宣传/预告可用本流程。完整多人长访谈、长纪录片或需要大量剧情连续性决策的整片剪辑，转到相应长素材流程；可接收它整理好的选段表继续做短片。

损坏文件、缺失音轨、黑帧、可变帧率对齐偏差或不支持编码先处理最小样段。源不可用时不要擅自找相似素材冒充，列出受影响镜头及补充选项；无法听音时如实保留待审状态。整个素材目录不可读时先交缺项与可执行的补救步骤，不凭空编造取段结果。
