# 制作流程与数据约定

## 从需求到时间轴

新片形成简短brief，保留核心信息、输出规格、受众/平台、素材方式、声音模式、品牌与署名。已有片修改先读现状，保留用户改动。风格要变成可观察参数：例如构图尺度、入场时长、镜头密度、音乐抬升、粒子数量与遮挡范围。

阶段交付和批准条件以[逐关引导](guided-stages.md)为准。默认需求、文案、分镜与素材、关键画面与样片、成片逐关推进；本文件提供各关内部的数据与执行规则，不能据此跳过待确认关卡。文案通过前不生成最终旁白，样片通过前不渲染整片；明确自动推进授权按其范围执行。

### 声音模式

| 模式 | 先确定什么 | 如何定镜头 |
| --- | --- | --- |
| 有旁白 | 文案、最终录音、逐句/逐词时间点 | 对齐语义落点，给阅读和呼吸留空间 |
| 只有BGM | 音乐授权、选段、主要节拍与高潮 | 按节拍和标题阅读时长，不创建虚假口播字幕 |
| 无声 | 信息顺序和文字阅读时间 | 用镜头/文字变化组织节奏，不强制加音轨 |

已有用户录音按实际语义和时间点使用。用户要求加快语速时保持音高并重算依赖时间点，不能只缩短画面。若保留录音但改了产品名/数据，先核对录音内容是否冲突，列出具体句子或时间点供用户取舍。

## 制作资料

按项目规模保留brief、共享镜头表、素材清单、声音/字幕时间点和验证结论，避免每个小改动都复制整套工程。

素材记录至少含assetId、本地路径、实际主体/地点、来源页、作者、许可、所做修改。生成图另记生成方式与用途。数据声明记录对应来源，不以搜到的图片标题代替内容核实。

用户视频、录音按[用户素材剪辑](user-media-editing.md)先检查，保留原件和源入出点、变速、裁切及原声策略；素材不必转换成静态图。共享镜头表的视频镜头扩展这些字段，不能只有成片时间而无法追溯来源。

分镜按[A-roll/B-roll指南](a-roll-b-roll.md)先安排主线信息与对应证据。逐镜标记rollRole（A/B/G）、narrativeRole与supports；有主线音轨时记录mainNarrativeAudio，素材原声另外记录策略。角色是片段在当前叙事中的作用，不是素材文件固定类别，不要求固定比例。

共享镜头表可以采用以下字段，数值仅为示例：

```json
{
  "engine": "hyperframes",
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "durationFrames": 1350,
  "audioMode": "narration-music",
  "mainNarrativeAudio": "narration-final",
  "seed": 20261110,
  "captionTerminalPunctuation": false,
  "scenes": [
    {"id": "opening", "from": 0, "durationFrames": 90, "assetId": "city-photo", "title": "主题标题", "layout": "center", "rollRole": "B", "narrativeRole": "establish-context", "supports": "旁白第一句：介绍城市环境", "audioPolicy": "no-source-audio"}
  ]
}
```

引擎名按所选项目，audioMode可为narration-music、narration、music-only或silent。镜头数不固定；上例仅演示字段，不是完整45秒时间轴。完整片要覆盖预定时长并显式处理间隔、叠化和片尾。

帧区间为[from, from+durationFrames)，引擎用秒时再除以fps；音频保留采样级精度。叠化只延长照片层，旧文字在切点退场；结尾署名时间也计入总片长。

## 组装与迭代

引导模式下，在分镜与素材关通过后，先检查开场、密集镜头、高潮、结尾，再做含字体/图片/视频/特效/所需音轨的短片段交用户审阅；样片关通过后再组装整片。自动模式仍执行关键帧/样片的技术验证，按已记录授权推进，不新增逐关等待。首次接入且目标是视频文件时，验证直接跳帧、倒退和编码结果；只要求预览时验证浏览器与跳帧即可，不强制额外编码。不要只看浏览器自动播放。

左右与居中构图服从主体位置，避免遮挡人物、设备或地标。光效使用固定种子，以时间函数生成；不依赖定时器随机累积。短促推镜和落版放在有意义的切点，不用持续闪烁制造气势。

主线声音可连续覆盖B-roll；J/L-cut分别控制声画入出点，不让每次换画面都切断话音。素材自身的同期声按已确认策略处理。先检查“说到的操作/结果是否真的出现”，再增加冲击特效，不能靠包装代替证据。

在样片关交付[可见编辑预览](editing-dashboard.md)，把可换文案、色彩和媒体绑定到真实变量/props，验证保存后预览与渲染共用。界面未验证时如实标明，不为满足看板外观重建整个编辑软件。

母带混音或引擎分轨选一种主路径。配乐平滑避让人声，转场音效峰值受控，片尾自然结束；无旁白时不用人声避让包络。最终AAC编码后再检查响度。

文案、字体、标点、署名、局部光效修改只动对应对象；时长/配音改变再重排依赖段落。稳定对象ID和帧表，不用多个完整final-vN副本替代版本管理。

## 参数化与小批次

仅在用户实际提出批量需求时增加批次输入。每行有唯一id、文案/数据字段和必要媒体引用；校验必填字段、数据类型、过长标题、路径、输出重名及与录音的一致性。按id输出，逐项记录成功/失败，失败只重跑该项，不重做已完成项或引入批处理服务。

无法核实的数据先标记；录音冲突批次标为pending_decision而非成功，记录其id及冲突时间点，继续不受影响的批次。未经用户取舍，不交付声画不一致版本作为已完成成片。缺依赖或离线媒体缺失时，可完成已授权的本地代码/配置和分镜，说明哪些批次仍未渲染。已有Remotion工程继续用本地依赖与锁文件，不因示例优先HyperFrames就迁移引擎。

## 最终交付

按用户需要提供MP4/预览、可编辑工程、字幕、封面、素材与音乐署名。工程有独立依赖与运行说明，不依赖旧版本目录；验证ZIP完整性。质量标准见[质量检查](quality.md)。

技能包只含制作说明、参考规则与必要脚本；具体视频工程、媒体、运行缓存和评估输出留在各自项目/outputs中。
